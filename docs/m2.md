# Milestone 2 — terminals

Date: 2026-11-20. Builds on milestones 0 and 1; only what is new is listed.

## New

- **History**: `GET /api/sessions/{id}/screen?scrollback=N` returns up to N
  lines that scrolled off the top, oldest first (also `almighty term read
  --scrollback N` and `scrollback_lines` on the MCP `terminal_read` tool).
  The server keeps 5,000 lines per session.
- **Scrolling in the client**: the mouse wheel moves back through the
  history. Each client has its own position; the session itself is never
  left scrolled. A button shows how far back you are and returns to the live
  output; typing returns too.
- **Font metrics**: the client measures the terminal font instead of
  assuming a cell width, so columns and the cursor follow the real font.
- **Copy and paste**: Ctrl+Shift+C copies the selection, Ctrl+Shift+V pastes
  (bracketed paste when the application asked for it).
- **Session list**: a terminal opened by the agent of another session is
  nested under that session. Exit codes are shown, Windows status codes in
  hex.
- **Closing**: the close button on a running session asks whether to end it
  or **keep it in the background**. A background session keeps running and
  stays reachable by id (API, `attach`, agents) but leaves the default list;
  `almighty ls --all` shows it, `almighty bg|fg <id>` moves it. An exited
  session is removed without asking.

## Verified

- API test: history order, exact line counts, and that reading it does not
  move the session's own view.
- Desktop client in the headless container: wheel scrolling ("↑ 20 lines"),
  typing returns to live output, an agent-created session appears nested
  without a refresh, closing it from the list, the end/background question
  and sending a session to the background (then `ls --all` and `fg`).
- Web, Linux desktop and Android builds compile.

## Not verified

- Copy and paste: there is no clipboard in the headless container. Reading
  the clipboard also depends on the webview granting access.
- Touch scrolling of the history on phones (only the mouse wheel is wired).
- Windows.

## Still open for terminals

- Output already printed is not re-wrapped when the width changes.
- No mouse reporting to applications, no kitty keyboard protocol, no IME.
- Subagents are read-only transcripts; nested subagent attribution is
  untested because the runtime does not nest them today.
- Sessions do not survive a server restart.

## Added after the milestone

- **Background sessions in the client**: the sidebar lists them under "In
  the background"; one click brings a session back and opens it, the close
  button ends it.
- **Agent access screen**: the "Agent access" button in a terminal's bar
  lists the other running terminals and sets, for the agent of each one, no
  access, read, or read and type (the grants API).
- Checked in Chromium against a scratch server: a background session
  appeared in its list and came back; a grant set in the screen was stored
  by the server. Not checked on the desktop or Android builds.

- **tmux adapter**: `GET /api/tmux` lists the panes of the tmux server on
  the server's machine and `POST /api/tmux/adopt {pane}` opens one as a
  session (`almighty tmux`, `almighty tmux work:2.1` or `almighty tmux %3`,
  and "Open a tmux pane" in the sidebar). One session per pane: the session
  runs `almighty tmux-pane <id>`, a bridge that attaches to tmux in control
  mode, paints the pane (with up to 500 lines of its history), then shows
  its output and types into it with `send-keys -H`. Ending the session
  detaches the bridge; the pane and its process stay. When the pane closes,
  the session ends. `ALMIGHTY_TMUX_SOCKET` picks another tmux socket
  (`tmux -L`).
  - Size: a pane alone in its window takes the size of the terminal that
    shows it, by tmux's own rule that the client used last sizes the window
    (`window-size latest`). Other windows of the same tmux session follow,
    and everything goes back when the person uses their own tmux client. A
    pane of a split window keeps its size, so the person's layout does not
    move; it shows well in a terminal at least as large, and long lines
    wrap wrong in a wider one.
  - Checked on Linux with tmux 3.4 on a separate tmux socket: listing,
    opening a pane from the CLI and from the browser client, a shell and a
    full-screen program (`less`), typing from almighty and from tmux,
    resizing, closing the session with the program still alive, and the
    session ending when the pane's shell exits.
  - Limits: needs tmux 3.2 or newer (not checked on older ones); the agent
    tree does not see agents that were started inside tmux; paste mode and
    the like set before the pane was opened are not known to the session.
    Not available on Windows. An earlier version opened whole windows
    through a second tmux client; it was replaced by this one.
