# Milestone 3 — plugin host

Date: 2026-11-21. Host: Linux x86_64, Rust 1.99.1, wasmtime 51, dioxus-cli
0.7.10. Everything below was run unless it is under **Not verified**.

## What exists

- **Runtime.** Light plugins are WebAssembly components (`wasm32-wasip2`)
  run by the server with wasmtime. The interface is `wit/plugin.wit`: four
  exports (`poll`, `render`, `action`, `command`) and one import interface
  with the host functions. Structured values cross as JSON text.
- **Isolation.** Each call gets a new instance with an empty WASI context:
  no files, no environment, no sockets. Limits per call: 10 s of computing,
  128 MB, 200 outbound requests. One call at a time per plugin. A plugin
  keeps no memory between calls; state goes through the host's key-value
  storage.
- **Permissions.** The manifest lists what the plugin needs; everything
  else is denied by the host function itself:
  - `network`: exact hosts or `*.domain`. `https` only, except towards the
    local machine. Redirects are returned to the plugin, not followed, so an
    allowed host cannot bounce a request somewhere else.
  - `secrets`: only declared names can be stored or read. Values never
    appear in API replies or in the audit log.
  - `items`: `write` to emit; without `read` a plugin sees only its own.
- **Install.** `almighty plugin add <dir>` shows the permissions, asks, and
  uploads manifest + component. The server requires the approved set to
  equal the manifest, stores the component with its SHA-256 and checks it on
  every start. Install, removal, enable/disable and secret changes go to the
  audit log. Admins install; members act; guests look.
- **Connectors.** `[connector] poll_seconds` makes the server call `poll`
  on a schedule (never faster than every 30 s); `almighty plugin poll` does
  it on demand. Connectors emit items; emitting the same `external_id`
  updates the item.
- **Panels.** A panel is a tree of nodes (table in `PLUGINS.md`) that the
  Dioxus client draws with its own widgets. Buttons and forms send an action
  id back; the plugin answers with the new tree. The server pushes a
  "plugin changed" event, so an open panel refreshes after a poll.
- **Config files.** `workspace.toml` carries each plugin's configuration
  (read on every call); `users/<name>/layout.toml` orders and hides panels
  in that person's sidebar.
- **CLI.** `almighty plugin add | list | show | remove | enable | disable |
  secret | poll | panel | run | logs` and `almighty items`.
- **GitHub connector** (`plugins/github`, 163 KB component): open pull
  requests of the listed repositories, plus the ones waiting for your review
  when a token is stored; pull requests that disappear are marked closed.

## Verified

- Automated (`cargo test --workspace`, 22 tests): installing needs an admin
  and an exact approval; a file that is not a component is refused; panels,
  actions and form payloads; guests cannot act; storage persists across
  calls; configuration from `workspace.toml`; declared and undeclared
  secrets; a plugin without `read` sees only its items; allowed and refused
  hosts; an endless loop is stopped at the time limit and later calls work;
  disable; reload after a restart; a tampered component is not loaded;
  removal. The GitHub connector runs against a stand-in API: items, drafts,
  closing, review requests with a token, no credentials without one, a
  malformed repository name never becomes a request, API errors are reported.
- By hand, against the real GitHub API without a token: two public
  repositories, 100 open pull requests became items.
- Desktop client in the headless container: the sidebar lists the panels;
  the pull-request panel draws cards, badges and links; a link opens in the
  side browser; in the example panel a button and a form change the counter.
- Web and Linux desktop builds compile.

## Not verified

- Windows and macOS builds of the server with wasmtime; Android client.
- The GitHub connector with a real token (private repositories, review
  requests) — only against the stand-in API.
- The web client's panels in a browser (same code as desktop; compiled only).
- Panels on a phone-sized screen.
- `layout.toml` in the running client (the ordering logic is unit-tested).

## Known limits and open points

- Secrets are stored in the server's SQLite file (mode 0600), not encrypted
  and not in an OS keychain. They belong to the workspace, not to a person.
- The allow-list is by host name; a listed name that resolves to a private
  address is still reached.
- The debug server binary grew to 436 MB with the runtime; release size and
  start-up cost of compiling components are not measured. Components are
  compiled on every server start (no cache).
- A plugin call blocks one worker thread for its duration.
- Not built from the contract: service plugins, triage rules, item actions,
  agent tools (MCP), agent adapters, terminal access, events, `llm`,
  `notify`, web panels, install from a git URL or a registry.
- Markdown and diagram nodes are shown as plain text.
- Removing a plugin keeps the items it emitted.
