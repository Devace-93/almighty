# Milestone 7 — mobile: layout and push

Date: 2026-11-21. Host: Linux x86_64. Everything below was run unless it is
under **Not verified**.

## What exists

- **Phone layout** (screens up to 720 px wide): the menu (workspace
  switcher, inbox, panels, terminals) and the chosen view take turns on the
  whole screen; picking an entry closes the menu and a "Menu" button brings
  it back. Controls are at least 40 px tall; the inbox tabs scroll sideways;
  forms stack.
- **Push to a phone** without any server of the project's own:
  - a person registers one or more endpoints: a topic on an ntfy server
    (the ntfy app on the phone shows the notification) or any UnifiedPush
    endpoint;
  - the operator lists the hosts pushes may go to in `workspace.toml`;
    with no list, push is off:

    ```toml
    [push]
    allowed_hosts = ["ntfy.example.org"]
    content = "wake"      # default: says only that something arrived
    # content = "summary" # sends the title and the short summary
    ```

  - the same decision that raises a desktop notification (bucket,
    priority, the person's threshold and quiet hours) sends the push;
  - endpoints must be `https` on a listed host (plain HTTP only towards the
    server's own machine), redirects are not followed, and the list is
    checked again on every send.
- **Client**: "Phone alerts" screen to add, remove and test endpoints; it
  shows what the operator allows.
- **CLI**: `almighty push add <endpoint> [--label …]`, `list`, `remove`,
  `test`.
- The multi-workspace switcher exists since milestone 1.

## Verified

- Automated (`cargo test --workspace`, 46 tests): endpoint rules (look-alike
  hosts, credentials in the URL, other ports, missing topic, plain HTTP);
  push off by default; endpoints are personal; an item worth a notification
  is pushed with no content by default and with the summary when the
  operator chose it; a host removed from the list stops receiving and the
  endpoint reports why; header values cannot carry line breaks.
- By hand against a local stand-in for ntfy: `push add`, a refused host,
  `push test`, `push list`.
- Web client in Chromium at 390 × 780 against a scratch server: sign-in,
  the menu, the inbox with a real pull request, the phone alerts screen.
  This is also the first run of the inbox and panels in the web client.
- `dx build --android` compiles the client with every view added since
  milestone 2.

## Not verified

- A real ntfy server and the ntfy app on a phone; a UnifiedPush distributor.
- The Android build on an emulator or a device after these changes (last
  run there: milestone 0), and touch scrolling of terminal history.
- iOS (needs a Mac).

## Open points

- The app does not receive pushes itself: it relies on the ntfy app (or a
  UnifiedPush distributor) being installed. Receiving inside the Android
  app needs native code; iOS needs APNs and a decision between a self-built
  app and a content-free relay (brief, open decision 2).
- The clap argument of `push add` was first called `url` and collided with
  the global `--url`; found while testing by hand and renamed. No other
  subcommand has that clash.
- Tapping a push does not open the item: ntfy "click" actions need the
  workspace's public address, which the server does not know yet.
