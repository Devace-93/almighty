# Milestone 5 — review, explainer, rich terminal (first slice)

Date: 2026-11-21. Host: Linux x86_64. Everything below was run unless it is
under **Not verified**.

## What exists

- **Review.** An inbox item whose plugin declares `[review]` (GitHub pull
  requests today) opens in a review view:
  - the change: title, author, branches, totals;
  - a **risk map** computed on the server from paths and sizes, with the
    reason for every level (security-sensitive area, schema or migration,
    delivery pipeline, dependencies, large change, tests, documentation,
    generated lock file, diff not shown). No model involved;
  - notes such as "code changed and no test file was touched" or "the
    listing is incomplete";
  - the diff of each file, collapsed, with added and removed lines coloured;
  - an optional **summary** from the operator's model, on request: what the
    change does, what to look at, what to ask. The highest-risk files are
    sent first; files that do not fit are listed as not read.
- **Explainer.** "Explain selection" is available over every view: the
  selected text goes to the operator's model with a note of where it comes
  from, and the answer appears in a card, in the person's language. Without
  a configured model it says so. Selections over 20,000 characters are
  refused rather than cut.
- **Rich terminal.** Images printed with the iTerm2 inline-image sequence
  (`OSC 1337 ; File=…;inline=1`, what `imgcat` emits) are captured by the
  server, checked to be PNG, JPEG, GIF or WebP by their bytes, and shown in
  a strip above the terminal; click to enlarge. A plain attached terminal is
  unaffected. Up to 40 images of 8 MB per session, in memory.
- **Model provider** moved to `[llm]` in `workspace.toml` (`[triage]` is
  still read); triage, review summaries and the explainer share it.
- The side browser was already in place since milestone 0.

## Verified

- Automated (`cargo test --workspace`, 37 tests): risk scoring and
  ordering; the summary input dropping the least risky files when over
  budget; validation of the model's summary; review of a pull request
  through the GitHub plugin against a stand-in API (files, branches, notes,
  unknown item, no model configured → 503); the explainer against a
  stand-in provider (language, context, empty and oversized selections
  refused before any request); inline images (a real PNG kept, a non-image
  and a non-inline file ignored, served with its type and `nosniff`,
  authentication required).
- By hand, real GitHub without a token: the review of an open pull request
  (2 files, diff shown).
- Desktop client in the headless container, with a stand-in model command:
  "Review" from an inbox entry, the risk map, an expanded diff, "Summarize
  with the model", the image strip of a session, selecting a terminal line
  and "Explain selection".

## Not verified

- Summaries and explanations from a real model: only stand-ins were used,
  so their quality is unknown.
- Large pull requests (more than 100 files are flagged as incomplete, not
  paged), binary files, renames.
- Web client and phone layout for the new views (compiled only); Windows
  and macOS.
- `imgcat` itself and tmux passthrough; only a hand-written sequence.

## Not built from the brief

- Diagrams from blueprint, sketches from sketch and audio notes in a
  review, and the reverse path (proposing a change from a drawing, a diagram
  or a voice note): they need those plugins (milestone 6) and audio input.
- Images are shown in a strip, not at their place in the terminal grid; the
  cursor does not move as it would in iTerm2. No kitty graphics protocol, no
  sixel, no video, no link previews.
- Explaining a diagram node; an "explain" entry in context menus; a keyboard
  shortcut.
- Review of documents; comments or approval sent back to the source.
- The risk rules are fixed in code; they are not configurable per workspace.
