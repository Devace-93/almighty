# Milestone 0 — spike results

Date: 2026-11-20. Host: Linux x86_64 (Pop!_OS, COSMIC), Rust 1.99.1,
dioxus-cli 0.7.10. Everything below was run, not assumed, unless marked
**not verified**.

## 1. PTY + headless emulator + attach from your own terminal — works

Crates: `portable-pty 0.9`, `vt100 0.18`, `axum 0.8`.

- A session is a PTY plus a `vt100::Parser`; one OS thread per session reads
  the PTY, feeds the parser and broadcasts raw bytes.
- `almighty attach <id>` was run inside a tmux pane (standing in for any
  external terminal): the screen was redrawn from the emulator snapshot,
  typing reached the shell, output typed by an agent appeared live, the
  session took the pane's size (100x30), and `Ctrl-\` detached while the
  session kept running.
- Snapshot and subscription are taken under the parser lock, so an attaching
  client neither misses nor repeats output.
- vt100 0.18 notes: sizes are `NonZeroU16`; the window title is delivered
  through the `Callbacks` trait, not stored on the screen;
  `Screen::state_formatted()` already includes input modes.

## 2. Agent control interface — works

Same operations over HTTP, the CLI (`almighty term …`) and MCP
(`almighty mcp`, stdio): list, create, read, send_text, send_keys, wait,
resize, close.

- Key names are encoded from the emulator's modes. Verified in `nvim`:
  insert text, `Esc`, `Up Up` moved the cursor to row 0 (application/normal
  cursor handled by the encoder), `:wq` wrote the file.
- `C-c` interrupted `sleep 100`. Multi-line `send_text` used bracketed paste
  in bash (both lines stayed in the prompt until `Enter`).
- `wait` returns on regex (multi-line mode), idle time, process exit or
  timeout.
- Human priority: agent input is refused (HTTP 409) for 3 s after a person
  types, and while the session is locked; both verified.
- The MCP server answered `initialize`, `tools/list` and `tools/call`; tool
  failures come back as `isError` results.

Not done yet: per-agent permission scopes (any caller with the token can
drive any session), audit log to trace, kitty keyboard protocol, mouse.

## 3. Claude Code subagent tree — works

`almighty run -- claude …` adds `--settings` with three command hooks
(`PreToolUse` matcher `Agent|Task`, `SubagentStart`, `SubagentStop`) that run
`almighty hook`; the hook finds its session through `ALMIGHTY_SESSION` /
`ALMIGHTY_URL` in the PTY environment. The user's `~/.claude/settings.json`
is not touched.

Verified with Claude Code 2.1.329 (`claude -p`, two parallel subagents):

- `PreToolUse` carries `tool_name: "Agent"`, `tool_use_id`, and
  `tool_input {description, prompt, subagent_type}`.
- `SubagentStart` carries `agent_id`, `agent_type`; `SubagentStop` adds
  `agent_transcript_path`.
- Neither names its parent or its task, so the tree matches each start to
  the oldest pending `Agent` call with the same `subagent_type`. With
  parallel spawns of the same type the description can be attributed to the
  wrong sibling; the order observed was correct.
- Subagent transcripts are readable JSONL at
  `~/.claude/projects/<project>/<session>/subagents/agent-<id>.jsonl`; the
  server only reads paths under `~/.claude/projects`.

**Not verified:** nested subagents (whether tool hooks fired inside a
subagent carry `agent_id`), interactive subagents (the view is read-only),
other runtimes (Codex, Cursor, ACP).

## 4. Dioxus shell — web, Android and Linux desktop

One Rust crate (`crates/ui`), Dioxus 0.7.10, no JavaScript written by hand.

- Web (wasm): sidebar with sessions and agent tree, terminal panel, subagent
  transcript view, side browser panel, phone layout under 720 px. Checked in
  Chromium at 1280x720 and 390x780.
- Terminal rendering uses the **Rust path**: the server sends the emulator
  grid as styled runs (full frame, then changed lines, at most ~60 fps) and
  the client draws spans. Keys go back as key names. This needs no xterm.js
  and no JS interop, so it stays valid for a future Blitz renderer.
- Links in the terminal: click opens the side panel, Ctrl/Super+click and
  Alt+click fall through to the browser.
- The only platform-specific code is `src/net.rs` (WebSocket and sleep:
  `gloo` on wasm, `tokio-tungstenite` on native).

Known limits of the spike:
- Cell size is a constant (13 px font ≈ 7.83 x 17 px), not measured; a font
  with another advance width misplaces the cursor and the column count.
- No selection/copy handling, no scrollback view, no IME, no mouse reporting.
- The side browser on web is an `<iframe>`: sites that forbid framing
  (`X-Frame-Options` / `frame-ancestors`) will not load there.
- Sessions and agents are polled every 1.2 s; milestone 1 replaces this with
  a push channel.
- Debug wasm is 48 MB; release size and load time **not measured**.

Desktop (Linux): **builds and starts.** Needs
`libwebkit2gtk-4.1-dev libgtk-3-dev libxdo-dev libayatana-appindicator3-dev librsvg2-dev`.
`dx build --desktop` took 38 s and the process stays up with its WebKit
processes.
- Idle memory (debug build, RSS): app 197 MB + WebKit web process 175 MB +
  WebKit network process 55 MB ≈ 427 MB. This is the webview cost that a
  native renderer would remove; release numbers **not measured**.
- Confirmed by hand on a COSMIC desktop: the window lists the
  sessions, typing works, and the native side browser loads a page, resizes
  and closes.
- Dioxus desktop blocks every http(s) navigation in its own webview, iframes
  included, and sends the URL to the system browser. The side browser on
  Linux desktop is therefore one WebKitGTK view per tab laid over the panel
  slot (`crates/ui/src/sidebrowser.rs`).
- Tested in the headless container (`tools/guitest/`, X11): tabs, reuse of
  the tab for a link already open, closing a tab, closing the panel, icon
  buttons, typing and arrow keys in the terminal, and bare hosts
  (`google.com`, `wikipedia.org` linked; `main.rs` and an unresolvable name
  left as text).
- Terminal output already printed is not re-wrapped when the panel narrows
  the terminal; only new output uses the new width.

Android: **builds and runs.** `dx build --android` (NDK 27.2, SDK 35)
produced a debug APK (86 MB, first build 154 s). Installed on an emulator
(AVD, API 35) with `adb reverse tcp:8092 tcp:8092`: the same UI code listed
the sessions and drew the live terminal over the native WebSocket path
(`tokio-tungstenite`), in the phone layout.
- Typing: a touch input row (Esc, Tab, Ctrl-C, arrows and a real text
  field) appears on narrow or touch screens. Verified on the emulator with
  injected key events: text, Backspace, Enter, Ctrl-C, two commands in a
  row. The field is uncontrolled; a controlled one dropped characters
  because events cross a process boundary on native webviews.
- **Not verified:** a real on-screen keyboard with prediction/autocorrect
  (the delta logic for rewritten words is unit-tested only).
- **Not verified:** a physical device, release size, the side browser panel
  on Android, iOS (needs a Mac).
- The package id is the default `com.example.AlmightyUi`; set a real bundle
  identifier in `Dioxus.toml` before any distribution.

## Windows (run on a Windows 10 machine, 22H2 build 19045; Windows 11 not tested)

Built with a session-only workaround (gnullvm toolchain + rust-lld, TLS
features stripped in a scratch copy) because the machine has no C compiler;
msvc results are still missing.

Verified on Windows 10:
- Server: builds, key tests pass, `cmd.exe` and `powershell.exe` sessions
  work (echo, resize, Ctrl-C, exit codes, UTF-8 output).
- The emulator's reply to `ESC[6n` is required: ConPTY opens every session
  with it and stalls otherwise. With the reply, prompts appear.
- Exit detection through the wait thread: 10/10 short commands ended as
  exited with the right code and their last output; 150 ms was enough.
- CLI: run, term send-text/send-keys/wait/read/close, ls; human-priority 409.
- `attach` after two fixes (now in the tree): the console needs
  `ENABLE_VIRTUAL_TERMINAL_INPUT` or arrows and function keys never arrive;
  Ctrl-Z was read as end of input. Tested through a nested ConPTY, not in a
  real Windows Terminal or classic console window.
- Dioxus desktop: a minimal app and the real `crates/ui` build and run; the
  UI loaded the session list. A second native webview through
  `build_as_child` works and loads pages that refuse iframes.
- Idle memory, private bytes: 108–135 MB for app + WebView2; 350 MB with a
  second child webview in its own WebView2 environment.

Findings to act on:
- Port 8092 is reserved by HTTP.sys on that machine; use `ALMIGHTY_ADDR`.
- `ring` needs a C compiler, so the CLI/UI with TLS do not build there yet.
- Without `dx`, `asset!` CSS is not bundled: styled UI **not verified**.
- GNU targets need `WebView2Loader.dll` next to the exe; release builds
  need `windows_subsystem = "windows"`; the window title is still the
  default.
- `cmd` exits with 0xC000013A after a Ctrl-C'd command; a typed emoji is
  mangled in the shell's echo.
- Windows 11: ConPTY and the console VT modes exist there by the docs;
  WebView2 is preinstalled. None of it was run on 11.

## 5. Numbers

- Server RSS with two sessions and four clients: ~19 MB (debug build).
- Heavy output: `seq 1 300000` in a session with the web client attached
  took 2.1 s end to end (debug server); the client stayed in sync and showed
  the final screen. Server RSS after it: ~27 MB.
- Workspace: ~2,500 lines of Rust.
